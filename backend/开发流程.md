开发规划

你的题目和需求已经比较完整了，后端这边建议     
按“MVP先跑通，再逐步扩展”的方式推进。当前项目已
经有了 Spring Boot 基础骨架，下一步不要直接冲业
务细节，应该先把基础设施和核心数据链路搭好，否
则后面改动会很多。

建议整体分成 4 个阶段：

1. 基础工程阶段                                
   先把项目变成“可持续开发的后端骨架”。这一阶段
   做：

- 配置文件改成 application.yml
- 区分开发环境配置，比如 application-dev.yml
- 统一返回体 Result
- 全局异常处理
- 基础测试接口 /api/health
- 日志规范
- 接口路径统一前缀，比如 /api

这一阶段的目标不是功能多，而是让后面每个模块都
能按统一规范写。

2. 数据库接入阶段                              
   这个阶段要尽快做，不建议拖到最后。因为你的系
   统核心就是溯源数据链路，数据库模型会直接决定
   接口和业务结构。这里做：

- 接入 openGauss JDBC 驱动
- 引入 MyBatis
- 配置数据源、连接池
- 先跑通 SELECT 1 / SELECT version()
- 建立第一版表结构

核心表建议先定这几张：

- sys_user：用户
- sys_role、sys_user_role：权限
- base_info：基地信息
- product_batch：产品批次
- production_record：生产记录，包含种植/施肥/用
  药/采收等
- inspection_report：质检报告
- trace_code：溯源码/二维码信息
- recall_record：异常批次召回记录

这一阶段完成后，项目才真正进入“能开发业务”的状
态。

3. 核心业务阶段                                
   先做管理端，再做消费者端，因为消费者查询依赖
   前面的数据完整性。

管理端 API 优先顺序建议是：

- 用户登录
- 基地管理
- 批次管理
- 生产记录管理
- 质检报告管理
- 异常批次标记与召回
- 数据统计概览

消费者端 API 再做：

- 扫码查询溯源详情
- 展示基地信息
- 展示批次信息
- 展示生产过程
- 展示质检信息
- 异常批次提示

二维码模块穿插在批次完成后做：

- 生成唯一溯源码
- 建立批次与溯源码映射
- 查询时校验有效性
- 后续可扩展签名、防伪校验

4. 安全与收尾阶段                              
   最后再补系统级能力：

- JWT 登录鉴权
- RBAC 权限控制
- 接口参数校验
- 操作日志
- 全局异常码
- 基础缓存与索引优化
- 部署文档、接口文档、测试用例

后端技术方案落地

结合你的论文内容，后端推荐直接定成这一套，不要
再摇摆：

- JDK 17
- Spring Boot 3.5.x
- MyBatis
- openGauss
- HikariCP
- JWT
- Lombok
- Maven

包结构建议一开始就固定：

- com.yujia.backend.common
- com.yujia.backend.config
- com.yujia.backend.controller
- com.yujia.backend.service
- com.yujia.backend.mapper
- com.yujia.backend.entity
- com.yujia.backend.dto
- com.yujia.backend.vo

开发顺序

我建议你接下来按这个顺序推进：

1. 先补基础工程骨架
2. 立即接 openGauss + MyBatis
3. 设计并落地核心表结构
4. 先做管理端核心 CRUD
5. 再做二维码和消费者查询
6. 最后补鉴权、权限、优化和文档
